# コネクタ追加の手順

各ステップの終わりでユーザーに確認を取ること。勝手に次のステップへ進まない。

## 1. 調査と報告（コードはまだ書かない）
- 対象の DB が持つ固有の概念（型システム、方言、トランザクションの意味論、ページング、認証、エラー体系）を整理する。
- 既存のポート（インターフェース）にそのまま乗るもの、乗らないものを分類する。
- **乗らないもの**について、次のどれで扱うかを案として出す。
  - (a) Adapter の内側に閉じ込めて吸収する
  - (b) capability として「未対応」を明示する
  - (c) ポート自体を拡張する（影響が大きいので要相談）
- 推奨案と理由を添えて相談する。

## 2. 法則テストの確認
- 共通の契約テスト（法則テスト）が、このコネクタに適用できるかを確認する。
- 新しい性質が必要な場合は、テストを先に提案する。

## 3. 実装
- 固有の型、例外、設定は `connectors/<db>` の外に出さない。
- 境界で Domain のエラー型に変換する。原因（cause）は保持する。
- 未対応の機能は明示的なエラーにする。似た動作で代用しない。黙ってデフォルト値を返さない。

## 4. 検証と報告
- 契約テストと Property-based テストを実行し、結果をありのまま報告する。
- `abstraction-reviewer` サブエージェントでレビューする。
- 「できたこと」「未対応として明示したこと」「検証できていないこと」を分けて報告する。
