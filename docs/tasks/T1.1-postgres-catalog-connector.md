## 目的
データソースの構造（表、列、制約、コメント）を、DB に依存しない形（`Catalog`）で読み出す。抽出器（T1.3）の入力になる。

## 背景
仕様 6.1（接続）、6.6.3（スキーマ制約はカタログ読取の抽出器）、9.2（範囲指定）。CLAUDE.md の層構造（ポートは Domain、実装は Adapters/connectors）。

## AdventureWorks の実態（2026-10-15 調査）
- 本体 5 スキーマに 68 表。lorint の便利ビュー（`pe` / `hr` / `pr` / `pu` / `sa`、68 個）は範囲外
- 各スキーマにビュー計 21、マテリアライズドビュー 2
- 制約：主キー 68、外部キー 90、CHECK 88、UNIQUE 1。制約でない一意インデックス 2
- ユーザー定義のドメイン型 6（`Name`、`Flag`、`NameStyle`、`Phone`、`OrderNumber`、`AccountNumber`）。106 列が使う
- enum 型、継承、パーティション、トリガーは無い

## やること
- Domain：`Catalog`（表、ビュー、列、主キー、一意、外部キー、CHECK、コメント、型の別名）と、ポート `CatalogReader.read(scope) -> Catalog`、エラー型 `SourceError(cause)`
  - 列：名前、順序、ソース上の型名（文字列のまま）、中立な型族（整数、小数、文字列、真偽、日付、日時、バイト列、UUID、XML、JSON、その他）、NULL 可否、既定値、コメント、型の別名
  - 範囲（scope）：含めるスキーマの一覧
- Adapter（`mandara.connectors.postgres`）：psycopg 3 で pg_catalog を読む
  - `REPEATABLE READ READ ONLY` のトランザクション1つで読む（一貫したスナップショット）
  - 型名・CHECK の式は解釈せず文字列で運ぶ。型族への寄せは Adapter の中で行う
  - 継承、パーティション、式インデックスを範囲内で見つけたら「未対応」のエラー。読み飛ばさない
  - 接続情報は libpq の環境変数（`PGHOST` など）から。リポジトリに書かない
  - psycopg の例外は境界で `SourceError` に変換し、原因を保持する
- 契約テスト（全コネクタ共通）：
  - 主キー・一意・外部キー・CHECK が指す列は、その表に実在する
  - 範囲内の外部キーの参照先は、カタログに実在する
  - 同じ DB を2回読むと一致する（決定性）
  - 出力の順序が正規化されている
- テスト用 DB は fixture で作って消す。DB に繋がらなければ失敗にする（スキップしない）

## やらないこと

- ビュー定義の SQL の解析（T4.1）。ビューの存在と列は読む
- ストアドの定義、トリガー
