# T1.10 地図（geo.point のデコードと表示）

- 状態：完了（2026-10-15）
- 段：1　依存：T1.9

## 目的
`geo.point` の列を持つ表（AW の住所）を、地図に自動で出す。

## 背景
仕様 4.2（encoding の変換はコーデックの責務、DB コネクタは形式を知らない）、9.4（地図）。

## やること
- コーデック（Adapters の中、コネクタから独立）：`sqlserver_geography` → 緯度・経度。不正なバイト列はエラー
- 実データの読み（ゼロコピー）：表の行を取得する API。件数の上限を持つ
- MapLibre GL で点を出す。点を選ぶと行の詳細

## 完了条件
- 住所 19,614 行（の上限内）が地図に出る
- コーデックの法則テスト：既知の点の往復、不正な入力でエラー

## 決めること（2026-10-15 に決めた）
- 地図のタイル（オフラインで使えるもの、外部サービス）
- 行を読む API の形（T5.3 のグラフ問い合わせとの関係）

## 実装で決めたこと
- 下地は Natural Earth（v5.1.2、パブリックドメイン）の国境・州境を同梱（ui/public/geo、作り直しは scripts/prepare_basemap.py、元の SHA-256 を固定）。外部のタイル配信は使わない
- 点は、OM で意味の型が geo.point の列から。列の encoding のコーデック（mandara.codecs。I/O の無い純粋な変換なので Domain。DB コネクタから独立）で緯度・経度にする。encoding の変換先が geo.point であることも確かめる
- 実データは、serve --connect SOURCE CONNINFO で渡したソースから読む（ゼロコピー。ColumnReader ポートと PostgreSQL の実装）。点だけを返す API（上限 5 万件）
- 契約（①の PointSet）：点、NULL の数、変換できなかった行と理由、読んだ行の数（= 点 + NULL + 失敗）、上限、打ち切ったか
- 地図は選んでいる表の geo.point の列。無ければそう伝え、出せる列から選んでもらう
- MapLibre の Worker はバンドラが見つけられないので、Vite に Worker を（依存ごと）まとめさせて URL を渡す
- UI のスモークテスト（scripts/ui_smoke.mjs、check.sh に組み込み）：ヘッドレスの Chrome で画面を開き、ブラウザのコンソールのエラーで失敗にする。画像だけでは「空の地図」を見逃したため

## 第二弾（2026-10-18）：点からインスタンスへ、見え方とレイヤ
- 点を押すと、右の Drawer にインスタンスを出す（ドメインビューワと同じ部品 InstancePane）。「ドメインで開く →」と、Drawer の中の
  リンクはドメインの画面へ移る。Esc で閉じる。点の表がドメインでなければ、その理由を出す
- 見え方：平面 / 鳥瞰（傾けて、⟳ でゆっくり回す。地図に触ると止まる）/ 地球（globe）。空・大気・雲のような飾りは入れない
  （デジタルツインの計器盤として、情報を詰める方向）
- 計器（HUD）：経緯線（10° ごと。赤道と本初子午線は強く）、線画の陸（琥珀の細い国境・州境）、テレメトリ（カーソルと中心の緯度・経度、
  拡大率・傾き・向き、見えている点の数と割合、見えている範囲で点の多い升の上位 5。押すとそこへ寄る）、四隅の枠、中心の十字、走査線
- 気づいたこと：AdventureWorks の住所のうち 918 件（英国の Oxon、West Sussex など）は、ソースの値そのものが (0, 0)。
  デコーダの誤りではない（生のバイト列で確かめた）。地図は事実どおり (0, 0) に描く
- レイヤ（重ねられる）：光る点、ヒートマップ、クラスタ（押すとほどける拡大率まで寄る）、柱（点の広がりを約 48 升に割った件数の
  3D。高さと色は件数の平方根。押すとその升まで寄る）。色はその表のドメインのカテゴリの色
- 外部の配信は使わないまま（文字のラベルは無し。グリフの配信が要るため）
- 法則（テスト）：升への振り分けで、どの点もちょうど1つの升に入る（件数の和 = 点の数）。見えている範囲の数は範囲の中の点だけ
  （日付変更線をまたぐ範囲も）
