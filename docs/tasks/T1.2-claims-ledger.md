# T1.2 主張台帳（形式と置き場所）

- 状態：完了（2026-10-15）
- 段：1　依存：なし

## 目的
抽出器が出す「ソースについての主張」を、OM と同じ仕組み（①で定義、生成した型、検証、往復のテスト）で扱う。OM の `evidence` は主張の ID を指す。

## 背景
仕様 6.6.2（主張の形式）、6.6.5（既定確信度）。決定（2026-10-15）：決定的な抽出器の主張は git に乗せず、ID は内容のハッシュ。

## やること
- ①（LinkML）に `Claim` を定義：`id`、`subject`（表 / 列）、`predicate`（閉じた enum）、`object`、`source`（kind、場所）、`extracted_by`、`valid_at`、`confidence`
  - 段 1 で要る述語だけを置く（例：主キー、一意、参照、NULL 不可、コメント、CHECK、型の別名）。足すときは①を変える
- ID：主張の内容（subject、predicate、object、source）の正規形からハッシュで決める。抽出器の版や実行時刻は含めない
- ストア（Adapter）：`work/<source>/claims/<schema>/<table>.yaml`。表ごとに1ファイル、固定のキー順
- 法則テスト：往復、冪等、ID の決定性（同じ内容 → 同じ ID、違う内容 → 違う ID）
- 仕様の更新：5章（`claims/` の置き場所）、6.6.2（ID の決め方、git に乗せないこと）
- `.gitignore` に `work/`

## やらないこと
- レビューの回答・LLM の主張の保存方針（T3.6）

## 完了条件
- `Claim` の型が①から生成され、ストアの往復・冪等・ID の法則テストが通る
- 仕様 5章・6.6.2 が決定と一致している

## 実装で決めたこと
- 値は、述語ごとに形を決めた構造（`object` の自由な辞書ではない）。述語ごとに、主語の粒度（表 / 列）と、持つべき値のフィールドを `mandara.om.claims.SHAPES` に持ち、検証で強制する
- 主語はソース上の名前（source、schema_name、table、column）。OM の安定 ID より先に作られるため。`schema` は pydantic と衝突するので `schema_name`
- ID は `clm_` ＋ 内容の正規形（JSON、キー順固定）の SHA-256 の先頭 16 桁
- 型族（TypeFamily）と外部キーの動作（ReferentialAction）は、カタログと主張で共有するので①に移した
- 台帳の書き込みは丸ごと置き換え。台帳の形でないファイルが混ざったディレクトリは消さずにエラー。台帳が無いことを0件と取り違えない
- 台帳のファイル名は、ソース上の名前を可逆に符号化する（[a-z0-9_-] 以外のバイトは %XX）。"/"、".."、大文字小文字の違い、Unicode の正規化の違いで、root の外に書いたり黙って上書きしたりしない
- 書けるのは決定的な出所（schema / sql / codelist）の主張だけ。書く前と読む境界の両方で主張を検証する（手で編集されたファイルは信頼できない入力）
- ID の正規形は、含めるフィールドを明示して組み立てる。①にフィールドを足しても既存の ID は変わらない。算出が変わったことはゴールデンテストで検出する
- 列の並びは、ソースが宣言した順のまま ID に含める
- 書き手は1つを前提にする（ロックは持たない）。Finder が作る `.DS_Store` などが台帳に混ざると、読み書きはエラーになる
