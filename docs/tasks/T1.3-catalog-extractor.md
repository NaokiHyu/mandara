# T1.3 カタログの抽出器（カタログ → 主張）

- 状態：完了（2026-10-15）
- 段：1　依存：T1.1、T1.2

## 目的
`Catalog` から、決定的な主張（`source.kind: schema`）を作る。純粋な関数で、DB に触れない。

## 背景
仕様 6.6.3（スキーマ制約はカタログ読取、決定的）、6.6.5（スキーマ制約の既定確信度 1.0、コメントは別）。

## やること
- 主キー、一意、外部キー、NULL 不可、CHECK、コメント、型の別名を、それぞれ主張にする
- 確信度は 6.6.5 の既定に従う（制約 1.0）。コメントの確信度を決める（6.6.5 に無い）
- 主張を T1.2 のストアに書く

## やらないこと
- 主張の解釈（どの関係型か、どのドメインか）は T1.4 / T3.2

## 完了条件
- 法則テスト：同じカタログから同じ主張集合（ID を含む）が出る。カタログの各制約に対応する主張がちょうど1つある
- AW で、外部キー 90 本 → 参照の主張 90 件、などの数が一致する

## 実装で決めたこと
- コメントの確信度は 0.85（仕様 6.6.5 に行を追加）。AW でもコメントの誤りが 2 件ある
- カタログの事実はすべて主張にする（オブジェクトの種類、NULL 可・不可、既定値、列の位置も）。モデラーはカタログを直接読まず、主張だけを根拠にする
- NULL 可否は3値のまま：不可 → not_null、可 → nullable、宣言なし（ビューの列）→ 主張なし
- locator は出所の中の場所（`constraint "名前" on "スキーマ"."表"`、`column "スキーマ"."表"."列"` など）。SQL 標準の引用符で曖昧さなく書く
- 台帳への書き込みを呼ぶユースケースは T1.6（コマンド）で作る。T1.3 ではテストから書いて読めることを確かめた
