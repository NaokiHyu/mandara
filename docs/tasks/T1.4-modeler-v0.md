# T1.4 モデラー v0（規則だけで OM を提案）

- 状態：未着手
- 段：1　依存：T1.3

## 目的
カタログと主張から、`status: proposed` の OM を規則だけで作る。LLM は使わない。段 1 の通しを成立させる最小の推論。

## 背景
仕様 6.3（出力は proposed、confidence と evidence 必須）、4.2（表メタデータ）。

## やること
- 表：id、name、source、context、columns、identity（主キー、一意 → 代替キー。NULL 可の列を含む一意は代替キーにしない）
- 列：名前。ドメインは付けない（段 3）
- 関係：外部キー → `has` / `reference`、`n:1`、via は列の対応。自己参照は `self`
- 各提案の `evidence` は主張の ID、`inferred_by` はモデラーの名前と版
- 出力を検証（4.5）に通し、違反があれば失敗にする
- 書き出し先：`work/<source>/ontology/`

## やらないこと
- 列ドメイン、grain、役割、is-a、part-of、classified-as、enum、単位（段 3）

## 完了条件
- AW の出力が検証で違反 0
- 法則テスト：出力の関係はすべて、参照の主張を evidence に持つ。evidence の ID はすべて台帳に実在する

## 決めること
- **表種別（`kind`）は①で必須だが、規則だけでは決められない。** 案：(a) 規則で決まらないものは提案に含めず、kind を任意にした「提案用の形」を①に持つ、(b) 規則の当て推量（外部キーを2本持ち主キーがその組なら relation、ほかは domain）を低い確信度で出す。既定値で黙って埋めない
- コンテキスト（`context`）の決め方：当面はスキーマ名をそのまま使うか
- 表の安定 ID の採番（仕様 15.2：ULID 想定）。正解 OM は `tbl_<schema>_<table>` で書いている
