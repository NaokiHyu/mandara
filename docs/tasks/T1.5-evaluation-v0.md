# T1.5 評価 v0（正解 OM との突き合わせ）

- 状態：完了（2026-10-15）
- 段：1　依存：T1.4

## 目的
自動で作った OM を正解 OM と比べ、観点ごとの点数を出す。以降の段の改善を数字で見る。

## 背景
仕様 17.1、17.2（復元率、誤提案率、確信度の校正）。

## やること
- 突き合わせは安定 ID ではなく、ソース上の名前（表の `name`、列名、関係の via）で行う
- 観点：主キー、代替キー、関係（端点の一致）、関係型、列ドメイン、表種別、grain の有無
- 指標：復元率、誤提案率。正解の範囲（14 表）の外の提案は別に数える
- 結果を `docs/backlog.md` の点数表に転記する。`work/<source>/eval/` への書き出しは T1.6（コマンド）で行う

## 完了条件
- 正解 OM 自身を入力にすると、全観点で復元率 1.0・誤提案率 0
- 段 1 の出力で点数が出る（低くてよい）

## 実装で決めたこと
- どの観点も「事実の集合」の突き合わせ（mandara.evaluation.score.ASPECTS）。観点を足すのは、事実を取り出す関数を1つ足すこと
- 未決は事実を出さない（復元率は下がるが、誤提案には数えない）
- 関係は端点と型の2段。型は、端点が正解と提案の両方にある関係だけで測る（分母も）
- 採点の前に両方の OM を検証する。復元率・誤提案率は、分母が0なら測れない（None）。重複した提案は誤りに数える
- 法則：自分自身と満点、ID の付け替えに不変、事実に None が無い、局所性（関係を1本消すと端点の取りこぼしだけが1つ増える）、感度（種類を変えると誤りと取りこぼしが1つずつ）
- 採点の法則テストが見つけた OM の穴を、不変条件にした：同じ列の組のキーの重複（DUPLICATE_KEY）、同じものを結ぶ関係の重複（DUPLICATE_RELATION）。モデラーは中身の同じ外部キーを1つの関係にまとめる
- 正解の範囲の外の表・参照先への提案は採点せず、件数だけ数える
- 段 1 の AW の点数は tests/test_evaluation.py で固定する（回帰の検出）
