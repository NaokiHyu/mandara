# T1.8 UI の土台

- 状態：完了（2026-10-15）
- 段：1　依存：なし

## 目的
オントロジーUI とレビュー画面が乗る土台を作る。見た目の方向（エヴァのコンソールルーム、SF のオペレーションルーム）をここで決める。

## 背景
決定（2026-10-15）：TypeScript + React + Vite、MapLibre GL、Cytoscape.js。Python はローカルの HTTP API（FastAPI）。境界の契約は OM ファイルと JSON。仕様 9.1、9.4。

## やること
- Python の HTTP API（Application 層の上の薄い入口）：OM の一覧・表の取得
- TS の型を①から生成（LinkML の `gen-typescript`）し、手で型を二重に書かない。生成物の食い違いを検査する
- React + Vite の骨格。`ui/` に置く
- 見た目：配色、文字、パネル、グリッド、動きの方向を決め、トークン（CSS 変数）にする。案を2〜3出して選んでもらう
- 別言語の出力は信頼できない入力として、受け取る側で検証する（CLAUDE.md）

## 完了条件
- API から正解 OM を取得して画面に出せる
- 型の生成と食い違い検査が CI 相当のテストで回る

## 決めること
- 見た目の方向（案から選ぶ）
- UI のビルド・依存管理（npm / pnpm）

## 動かし方
```
uv run mandara serve --gold adventureworks=evals/datasets/adventureworks/gold/ontology   # API（127.0.0.1:8765）
cd ui && pnpm dev                                                                       # http://127.0.0.1:5173
scripts/check.sh                                                                        # すべての検証（Python と UI）
```

## 実装で決めたこと
- 見た目は案 C「静かな司令室」（炭色の地、琥珀の文字、装飾なし）。色・文字・間隔は ui/src/theme.css のトークン
- パッケージ管理は pnpm
- プロセス境界の契約は①に置く：OntologyDocument（OM 全体）と OntologyIndex（見られる OM の一覧）。TS の型と JSON Schema は①から生成（scripts/gen_ui_types.sh）。gen-typescript が出さない date 型はスクリプトで補う
- UI は受け取った文書を Ajv（strict、日付などの format も）で検証してから型として扱う。失敗は理由と中身を見せる
- 言語をまたぐ契約テスト：Python が生成した文書（Hypothesis の 40 件と正解 OM）を、UI の検証器が受け入れる。契約に合わない文書（ID の形、必須の欠け、閉じた集合の外、余分な項目、日付の書式）は拒否する
- API は読むだけ。127.0.0.1 にだけ立て、Host ヘッダも localhost に限る（DNS リバインディング対策）
