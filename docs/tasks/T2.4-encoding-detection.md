# T2.4 物理的な表現（encoding）の検出

- 状態：完了
- 段：2　依存：T1.3（T2.1 の統計は使わない。見本の値を直接読む）

## 目的
バイト列の先頭などから、列の encoding を機械的に判別する。

## 背景
仕様 4.2（encoding）、6.6.2（主張 `encoded_as`、出所 `data`）

## 決めたこと
- コーデックはプラグイン：`mandara.codecs.codec.Codec`（encoding、`matches` = 形の判定、`decode` = 変換）。
  足すときは `mandara/codecs/` にモジュールを1つ作り、`registry.CODECS` に1行足す。encoding の名前は①の閉じた集合なので、先に①の `SourceEncoding` に値（と `decodes_to`）を足す
  - 外部パッケージからの読み込み（entry points）はしない。外部のコーデックが出てきたら、encoding を閉じた集合から開くかと一緒に決める
- 判別（`mandara.codecs.detect`）：見本の NULL でない値をすべて matches かつ decode できたコーデックがちょうど1つのときだけ決める。
  2つ以上・一部だけ・読めないものは決めず、理由を実行の記録（`encodings`）に残す
- 抽出（`mandara.extractors.values`）：型族が binary の列だけ、主キーの順に先頭 100 行を読む。主キーの無い表は見ない（理由を記録）。
  決まったら主張 `encoded_as`（確信度 0.95）。規則のモデラーが列の `encoding` を提案する（確信度 0.95、根拠に主張）
- encoding のある列には、その変換先の値の型の意味型だけを問う・当てる（`value_types.assignable`。ENCODING_MISMATCH を問わない）。
  encoding は OM の列のものを使う（主張から引くのは規則のモデラーが提案するときだけ。人の判断と食い違わないように）。
  型族と encoding が矛盾していればエラー（IncompatibleEncodingError）
- 1列に encoded_as が2つ以上ある台帳はエラー

## 未決（相談事項）
- encoding は列の注釈（status・confidence）に畳んでいて、encoding だけを却下・修正する単位が無い。独立の判断単位にするか
- 主張の確信度 0.95 は見本の数に依らない定数。見本の数（と打ち切り）から決める規則にするか

## 法則のテスト
- 登録したすべてのコーデックに：decode が通る値は matches も真、encode → matches → decode で戻る、そのコーデックで書いた見本はそのコーデックに判別される
- 割れる場合（2つに当たる、一部だけ、形は合うが読めない、NULL だけ）は偽のコーデックで
