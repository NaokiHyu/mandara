# T2.6 値の似かた：同じ意味の列を、値の形と分布から見つける

- 状態：第 1 波は実装と測定まで。事実の渡し方は E（別の問い）に決めた（2026-10-19）
- 段：2　依存：T2.2（包含の測定と同じ位置に置く）

## 目的
宣言・コメント・列名が無くても、値そのものから「同じ意味型の列（兄弟）」の手がかりを出す。目標（メタデータの無い DWH 風の表や
CSV / Excel から OM を起こす）では、名前の手がかりが消えるので、値の形と分布が主役になる。

## 背景（研究の地図。2026-10-18 の調査）
- 構文パターンの学習：Potter's Wheel（MDL で構造を選ぶ）、FlashProfile（OOPSLA'18、パターンの選言で要約）
- 意味型の検出：Sherlock（KDD'19。文字の分布・全体の統計などの特徴量）、Sato、Pythagoras（数値の列）
- 圧縮による距離：NCD（正規化圧縮距離。コルモゴロフ複雑性の近似）
- 分類器 2 標本検定：C2ST（2 つの列の値を見分ける分類器が偶然より当たらなければ、同じ母集団）
- 列の埋め込み：Starmie（対照学習した言語モデル）、D3L（名前・重なり・形式・分布・埋め込みを束ねる）
- 実務の定石（Purview、Google SDP）：パターン → 検証 → 文脈 → 確信度の段階

## 決めたこと（ユーザーと合意）
- 信号は**プラグイン**。互いに独立に測り、**組み合わせは判断モデル**（Jev）に任せる。重みを手で決めて足さない。
  後で足すルールも、同じ「事実を出す」形で足す
- **D3L はプラグインにしない**。名前・重なり・形式・分布を束ねる、という D3L の考え方は、この全体の構成そのもの
- **Starmie は第 2 波**。手元の学習済みモデルで、対照学習はしない（「Starmie 風」と名乗る）。値を外の API に送らない
- **Sherlock の学習済み分類器は使わない**（DBpedia の 78 種類で、意味型の体系が合わない）。特徴量の考え方だけを使う
- 第 1 波：枠組み、構文パターン、特徴量、NCD、C2ST、段 3 の世界、評価

## 作り（第 1 波）

### 値を読む（ポート `source/samples.py`）
- `ValueSampler.sample(schema, table, column, limit)`：NULL を除いた異なる値を、値の文字列のハッシュの順に先頭から limit 個
  （決定的。同じデータなら同じ見本）。NULL を除いた行の数と、異なる値の数も同じ読みで返す
- 共通の法則（`tests/sample_laws.py`）を偽物と PostgreSQL の両方に当てる

### 測る（Domain `mandara/resemblance/`。純粋）
- 値の文字列表現（`render`）は Domain で 1 通りに決める（DB に依らない）。決められない型はエラー（黙って str にしない）
- **列ごとの要約（`shape`）**：
  - 値を「原子」の列にする：数字の並び、大文字の並び、小文字の並び、そのほかの文字の並び、空白、記号（記号はそのまま）
  - 一般化の段：1 = 文字の種類と長さ（`9{5}`）、2 = 文字の種類だけ（`9+`）、3 = 文字の種類の集合だけ。見本は異なる値なので、
    値そのものを書く段は持たない（繰り返しの無い値は、値のまま書いても短くならない）
  - **MDL** で段を選ぶ：パターンの記述の長さ ＋ パターンを使って値を書く長さ、が最も短い段（和は正確に丸めるので、値の並びに
    依らない）。FlashProfile / Potter's Wheel の考え方
  - 主張 `shaped_as`：選んだ段の上位のパターンと、それに当たる値の割合。**値の文字列は入れない**。共通の接頭辞のような定数の
    原子も入れない（複数の値に共通でも、姓や秘密の接頭辞のようなデータそのものでありうる。レビューの指摘。入れるかは要相談）
- **列の組の信号（プラグイン）**：どれも「測った値」と「同じ母集団ならこのくらい」の**基準**を返す
  - `pattern`：パターンの分布の重なり（1 − 全変動距離）。基準は、各列を半分に割った 2 つの重なりの小さい方。基準が 0.1 以下
    （列の中でもパターンが揃わない）なら近いと言わない。8 値以上で測る
  - `ncd`：NCD(A, B) = (C(AB) − min(C(A), C(B))) / max(C(A), C(B))。C(AB) はつなぐ両方の順の平均（対称）。値は
    (NCD(A₁, B₂) + NCD(A₂, B₁)) / 2、基準は各列の半分どうしの NCD の**平均**（大きい方にすると、圧縮の効く列と効かない列の組が
    近く見える）。16 値以上で測る（少ないと圧縮の固定の部分が距離をぶらす）
  - `c2st`：値ごとの特徴量（長さ、文字の種類の割合、数として読めるか、桁、0 埋め、エントロピー …）で、値がどちらの列の
    ものかを当てる **k 近傍（1 つ抜き）** の正答率。基準は、ラベルを並べ替えた正答率の 95% 分位点（**並べ替え検定**。近傍は
    1 回だけ求めるので安い）。最初はランダムフォレストの交差検証にしたが、組ごとに 79 ms かかったので変えた（1.2 ms）
- 数え方は乱数を使わない（並べ替えの乱数も種を固定）。同じデータ・同じ版なら同じ主張。pattern と ncd は組の向きに依らない。
  c2st は同じ距離の近傍を見本の順で選ぶので、向きで少し変わる（組は名前の順で 1 つなので、主張は決定的）

### 足切りと並列
- 比べる列：表（ビューではない）の列で、型族が比べられるもの（文字列・uuid、整数、小数、日付・日時）。真偽値・バイト列などは比べない
- 列の組は型族の群の中だけ
- 安い信号（`pattern`、`ncd`）は全部の組で測る。重い信号（`c2st`）は、安い信号のどちらかで列ごとに近い順 K 個に入った組だけ
- 主張にするのは、どれかの信号で列ごとに近い順 K 個に入った組（順位だけで決める。解釈の閾値で落とさない）。落とした組の数、
  値が少なくて測らなかった信号ごとの組の数、実際に使ったプロセスの数は、実行の記録に残す
- 組の計算は、プロセスを分けて並列に回す（Application。値は列ごとに一度だけ読む）
- 値の似かたの組（`resembles`）は名前の順で前の表に置くが、両方の表の材料になる（後ろの表の答えの根拠としても確かめられる）

### 主張
- `shaped_as`（列）：`patterns`、`pattern_shares`、`shape_level`、`distinct_values`、`sampled_values`
- `resembles`（表。columns → target の target_columns）：`method`（信号の名前と版）、`score`、`baseline`、
  `sampled_values`、`target_sampled_values`。組の向きは名前の順で 1 つ（対称な信号だけ）

### 組み合わせる（モデラー `modeler/resemblance.py`、`modeler/same_meaning.py`。2026-10-19 に E に改めた）
- 信号ごとの「読み方」（近いかどうか、事実の文）もプラグイン。`method` の名前で引く
- 分類（判断モデル）の列の意味型の問いには、値の似た列の事実を**入れない**（最初は入れていた：D。段 2 で判断が引かれた。下の測定）
- 判断モデルと LLM の材料（`state`、`brief`）に、列の値の形（`shaped_as`）を足す
- 表の分類が全部済んだ後に、すべての信号が近い組ごとに「同じ意味か」を判断モデルに問い、同じなら意味型を渡す（`same_meaning`）
  - 問わない組：受け取る列が人の判断済み・外部キーの組・型の合わない意味型・単位の要る意味型・時刻の役割を持つ別の表の意味型
  - 当てない答え：連鎖（受け取る列が別の答えの渡す側、または渡す側が別の答えで変わる）、1 つの列に別々の意味型（矛盾）
  - 上書きでは前の根拠を持ち越さない。元の意味型と、使う列の無くなった意味型を記録する
- 決めるのは判断モデル。似ていることは決め手ではなく根拠の 1 つ（注文番号と請求書番号は同じ形でも別の意味）

### 評価
- `mandara eval-resemblance`：正解 OM の同じ意味型の列の組を正解にして、信号ごとに
  - 列ごとの最も近い列が兄弟である割合（precision@1）と、兄弟を近い順 K 個に拾えた割合
  - 外部キー・包含でつながっていない兄弟だけでも同じ数を出す（値の包含では拾えないところ）
- 段 3 の世界（列名を崩す）を作り、LLM ありの実行で semantic_type_pairs と column_types を、信号ありと無しで比べる

### 残り（第 2 波と相談事項）
- 外部キーで同じ意味の組（`meaning.same_meaning_groups`）は、宣言された外部キー（references の主張）だけから作る。名前の無い
  参照（3b）で OM に足した関係は組に入らない。伝播と同じ意味の問いの両方に効く既存の穴（レビューの指摘。未着手）
- 列の埋め込み（Starmie 風、手元のモデル）。依存が重いので入れるかを決める
- パターンに共通の文字列（`"AW"9{8}`）を書くか：今は書かない（データの漏れになりうる）。書くなら T2.1 で規則を決める
- uuid は 16 進の原子が無いので段 3（文字の種類の集合）に潰れる。原子を足すかは未決
- c2st の距離は BLAS で計算するので、マシンが違うと同じ距離の近傍の順が変わりうる（同じマシンでは決定的）
