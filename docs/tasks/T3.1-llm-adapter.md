# T3.1 LLM の Adapter

- 状態：完了（2026-10-15、本物の API での確認は .env を置いてから mandara llm-check）
- 段：3　依存：なし

## 目的
LLM を外部 I/O として扱う Adapter を作る。

## 背景
CLAUDE.md（LLM は Adapter に閉じ込める、出力は信頼できない入力）

## やること
- Domain のポート：構造化された問いと答え。SDK の型は Adapter の外に出さない
- 実装：Claude API（llm/anthropic）。モデル名・版・実行 ID を記録する
- 出力は主張・提案の形式だけ。検証に失敗したらエラー。黙ってリトライしない、別モデルに切り替えない
- テストは記録した応答で回す（実 API を毎回呼ばない）。記録の作り方を決める

## 完了条件
- 不正な出力がエラーとして表に出ることをテストで確かめる

## 決めること
- API キーの渡し方（環境変数）
- 費用の上限

## 実装で決めたこと
- ポート（mandara.llm.model）は Domain、Claude の実装（mandara.llm.claude）は Adapter、設定と単価表の読み込み（mandara.settings）は Adapter
- 構造化された答えだけ：答え専用の道具（answer）を1つ渡して使わせる。切れた・道具を使わなかった・オブジェクトでない、はエラー。SDK の自動リトライも切る（max_retries=0）
- 予算（1 回の実行の上限。円で受け取り、為替でドルにする）：送る前に最悪の費用（数えた入力 ×1.1 を切り上げたトークン数で段を選ぶ ＋ 出力の上限）を見積もり、超えるなら送らない。送った後は成否にかかわらず課金されうる費用を累計（不正な答えは実際の使用量、送った後の失敗は最悪の見積もり）。実際の費用が見積もりを超えた・キャッシュの課金があった場合は、以後は送らない
- 単価は config/llm_prices.yaml（出典と確認日つき）。表に無いモデルはエラー
- 設定：.env（git に乗せない）と環境変数（優先）。.env は任意。既定の為替・予算は持たない
