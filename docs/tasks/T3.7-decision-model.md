# T3.7 分類は判断モデル（Jev）、名前と文は LLM

- 状態：着手（2026-10-16）
- 段：3　依存：T3.1, T3.2

## 目的
モデラー v1 の問いを「分類」と「生成」に分け、分類は判断モデル（TypeSafe の Jev。System One モデル）に、
名前と文の生成は従来どおり LLM に任せる。

## 背景
- T3.2 の再実行（2026-10-16、¥9.60）で、失敗はすべて答えの形の問題だった：出力の上限で切れた（2 表）、
  配列を文字列で返した、値の型の外の値（`boolean`）、根拠に主張 ID ではなく文を書いた（4 表）。予算で 43 表に届かなかった
- 表ごとの答えの大半は閉じた集合からの選択（表種別、関係型、意味型の割り当て、値の型、役割、加法性、単位）
- Jev は選択肢を決めて問い、選択肢ごとの確率と確信度を返す。型の外の値は返らない。出力は無料、入力 $0.042/Mtok
  （出典 https://docs.typesafe.ai/models 、2026-10-16 に確認）

## 分け方（表ごとに最大 5 回。要らない問いは送らない）
1. 分類（Jev）：表種別（domain / relation / event / unclear）、外部キーごとの関係型、辺（種類 × 向き。relation の表の
   候補のときだけ）、列ごとの意味型（型族で当ててよい既存の語彙 ＋ new）
2. 命名（LLM）：1 で new になった列に、意味型の名前・説明・enum の値（コメントか CHECK が述べるときだけ）
3. 意味型の性質（Jev）：2 で名付けた意味型の値の型（列の型族で当ててよいものだけ）、役割、加法性。requires_unit は値の型から
   コードで決める（money / quantity）
4. 単位（Jev）：単位の要る意味型の列の単位（固定の単位 ＋ 同じ表の code の列 ＋ unclear）
5. grain（LLM）：grain が要る表（event、または尺度を持つ domain）で、grain がまだ無いときだけ

組み立てた答えは、従来の検証（apply_answer）をそのまま通す。

## 決めたこと（2026-10-16 合意）
- ポート：Domain に判断モデルのポート（mandara.llm.decision）を LanguageModel とは別に置く。Jev の実装は
  mandara.llm.typesafe（Adapter）。HTTP API を直接呼ぶ（SDK の既定の再送と圧縮を避ける）
- 確信度：選んだ選択肢の確率。仕様 6.3 の閾値（既定 0.6）未満、または unclear は提案しない（理由つきで記録）
- 根拠：その問いの材料に入れた主張の ID（コードで決める）。誰の判断かは inferred_by に Jev と LLM の両方のモデルを書く
- 再送しない：429 / 529 もエラーとして表に出す
- 選択肢が上限（255）を超える問いは送らず、理由つきで記録する（黙って切り詰めない）
- 予算：Jev の費用も同じ上限（1 回の実行）に含める。入力トークン数の最悪は、送る本文のバイト数の 2 倍
  ＋ 固定の上乗せで見積もる（実測：小さな問い 2 つで 276 トークン）。実際が見積もりを超えたら以後は送らない（T3.1 と同じ）

## レビュー（abstraction-reviewer、2026-10-16）で直したこと
- 選択肢の上限は判断モデルの能力（DecisionModel.max_options）として受け取る。確率の和の許容は実装が渡す（Jev は丸めのため 0.05、実測の最大 0.01）
- 答えたモデルの版が問うた版と違えば不正な答え。上限を超える問いは送らず、予算にも記録しない
- どの問いにも unclear を置く。命名が値を挙げたかで enum を候補に入れるか決める。命名が既存の語彙の名前を返したら落とす
- 使わなかった辺、単位の列の根拠、受け取った不正な答え（記録で上書きしない）、分類が無くても grain を問う
- inferred_by の作者の区切り（" + "）をモデル名の連結に使わない
- 命名・性質・単位・grain の段の失敗は、その段の項目だけを落として続け、段の失敗として記録と CLI に出す

## 未決・既知の弱点
- Jev は英語が主。意味型の説明（日本語）を選択肢の説明に使っている
- 選択肢の順で先頭寄りに偏ることがある（作り手の申告）。順を変えて答えが揺れないかの確認はしていない
- enum の値の根拠だけは LLM に主張 ID を挙げさせている（grain の根拠は主キーと表のコメントの主張でコードが決める）

## 相談で決めたこと（2026-10-17）
- 段の失敗（命名・性質・単位・grain）は、その段の項目だけを落として続ける（失敗は記録と CLI に出す）
- LLM が名付けた意味型（とそれを当てた列）の確信度は 0.7 まで（NAMED_CONFIDENCE。名前は確率を測っていない）
- 予算は 1 回 20 円
- 問いの材料を絞る：意味型の説明は材料（state）に1回だけ置き、選択肢には名前と値の型・役割だけ。LLM には語彙の名前だけ
- フラグ列（boolean）は true / false の enum として、ラベルを列のコメントから付けさせる

## 相談事項（未決）
- 問いの文（プロンプト）が Domain（mandara.modeler）にある。CLAUDE.md は Adapter の責務としている（T3.2 からの前例）。直すなら別タスク
