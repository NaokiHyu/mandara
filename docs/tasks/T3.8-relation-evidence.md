# T3.8 関係型の手がかり

- 状態：完了
- 段：3　依存：T3.7

## 目的
has / is-a / part-of の判断を、名前だけでなく、構造とデータの事実で支える。

## 背景
仕様 4.2（is-a の realized_by、関係型の推論の手がかり）、6.6.2（主張 covers_all、discriminated_by）

## 決めたこと
- is-a の選択肢は、主キーを共有する外部キーにだけ出す。上位のすべての行に下位の行がある（covers_all）ものには出さない（拡張であって下位の型ではない）
- 主キーを共有する外部キーについて、抽出で参照の被覆を数える（CoverageReader）。
  上位の行のうち下位の行がある行が、上位の区分の列（主キーでない文字列・整数・真偽の列、値の種類 20 以下かつ行の数の半分以下）の値とちょうど一致すれば discriminated_by。
  全体と区分の列ごとの数は1つのスナップショットで数える
- 共有主キーの判定は1つの関数（om.ontology.is_shared_key）。抽出、モデラー、検証（SHARED_KEY_MISMATCH）が同じものを使う。並びは問わず、自分自身への参照は除く
- 関係型の問いに事実を添える：主キーの共有 / 主キーに含まれる、ON DELETE CASCADE、NOT NULL / NULL 可（宣言が無ければ言わない）、被覆、区分の列。
  区分の列の値は文に埋め込まず、問いの discriminators に置く。根拠の主張 ID を問いの根拠に入れる
- part-of と has は基数で分けない（どちらも n:1）。part-of の決定は判断モデルに任せる（規則で決めない）

## 結果（AdventureWorks）
- 主キーを共有する 6 本：employee → person は persontype ∈ {EM, SP} で区分、password → person はすべての行
- 正解 OM の relation_types は 14/15 のまま（正解にある関係が少なく、もともと is-a・part-of は当たっていた）
- 変わったもの：password → person が is-a（0.65）から part-of（0.88）。is-a の確信度が上がった（salesperson → employee 0.69 → 0.9 など）

## 未決
- covers_all を「is-a を選択肢から外す」強い条件にしている。読んだ時点のデータの偶然（行の少ない表）でも成り立つので、事実として添えるだけにするか
- 被覆の数え上げは区分の列の候補ごとに上位の表をなめる。大きな表では重い
- 区分の列が無く一部だけを覆う参照（person → businessentity など）は、事実として「一部」を伝えていない（主張が無い）
