# T4.3 文書の抽出器

- 状態：未着手
- 段：4　依存：T1.2, T3.4

## 目的
PDF などの普通の文書（設計書、データ辞書、運用手順書）をデータソースとして登録し、そこから主張を抜いてコンテキストを補う。

## 背景
- 仕様 6.6（文書は意味の根拠。文書を AI に丸ごと読ませるのではなく、主張を抜いて台帳にする）、6.6.4（文書中の「顧客番号」がどの列かを当てる根拠づけ）、`sources.yaml`
- ゼロコピー：文書本体は元の場所に置いたまま。Mandara が持つのは主張と出所（ファイルとページ）だけ

## やること
- 文書を知識源として登録する（種類、場所、抽出器）
- 表・列への言及を見つけ、主張にする（出所の種類は design-doc、locator はファイルとページ）
- 紐付けは独立した提案としてレビューに出す（「設計書の『顧客番号』は customers.cust_no のことですか？」）。紐付かない主張は推論に使わない
- AdventureWorks では、公開されているデータ辞書を文書として使う

## 完了条件
- AW のデータ辞書から抜いた主張で、モデラーの点数がどう変わるかを測る
- 文書から正解が漏れていないかを、正解隠蔽テスト（T3.4）で確かめる
