# T5.6 運用室の見た目（Industry 暗色。claude.ai/design のモック）

状態：第一弾（2026-10-18）

## 目的
ユーザーが claude.ai/design で作ったモック「Mandara Ops Room」（引き継ぎの zip はリポジトリに置かない。
6 画面：1a 運用室の壁面、1b Explore、1c Model、1d Review、1e Objects、1f Query）を、今の UI に実装する。

## 決めたこと（2026-10-18、ユーザーと合意）
- 見た目は全体を Industry 暗色に切り替える。トークンは `ui/src/theme.css`：
  - 色：鋼の青の地（#121b24 / #15202b / #1d2d3d）、アクセント #94bce3
  - 文字：Barlow Condensed の見出しと Barlow の本文。`@fontsource` で同梱し、実行時に外部へ読みに行かない。OFL-1.1
  - 枠：角の無い細線の枠と、四隅の「+」の印（`.blueprint` と `<Corners />`）
  - 状態の色：ok / warn / bad の3色だけ
- 裏にデータが無い部分は、作り物の数字で埋めず、今は出さない。該当するもの：
  - ウォッチの通知、オペレーターの承認カード、命令ボタン
  - 尺度から作る KPI、取り込みの統計、監査
  - Model の保存（SAVE TO BRANCH）、Query の組み立て
- 順番：共通の枠 → Review → Objects → Explore → 運用室。Model（1c）と Query（1f）はバックエンドが要るので、
  後のタスクとして積む（下の「積んだもの」）
- 画面の言葉は日本語。小さな区切りの見出し（QUEUE など）だけ英大文字を残す

## 実装したこと
- **共通の枠**：
  - ヘッダ：◆ MANDARA、OM の選択、OM の要約、日本語のナビ、UTC の時計
  - ナビの並び：運用室・グラフ・一覧・地図・レビュー・ドメイン
- **レビュー（1d）**：
  - 問いのカードは細線の枠と印。問いは大きい見出し。主ボタン（Y）だけを塗る
  - 種類の問いは、D / R / E の選択肢のカードで答える
  - 右の列：確信度の分布（今の問いの列から数える。閾値以上を色で）、対象ごとの数、表の詳細
- **オブジェクト（1e。ドメインのインスタンス）**：
  - 上：エンティティグループと種類と is-a の小見出し、大きな名前、主な参照
  - 数字の帯：近隣の集まりごとの件数と、合計できる尺度の1つ目
  - 本体：近隣の集まりのタブ（中身は今までと同じ GroupPanel。集まりと集合が同じ、という原則はそのまま）
  - 右の列：プロパティと参照先
- **グラフ（1b）**：
  - 左に凡例（エンティティグループと表の数、関係型、表の種類）。地は方眼
  - 表を選ぶと、その近く（隣の表と関係）だけを明るく残して寄る
  - 詳細から「オブジェクトを開く →」。ドメインかどうかは API の DomainIndex で決める。ドメインでなければ理由を出す
- **運用室（1a）**。数字はすべて API の実データ：
  - 左：出来事（event）のドメインのカード。時系列のあるものを先に、件数の多い順。最新の区切りと前との増減、小さな棒
  - 中央：地図（地図の画面と同じ部品）。下に、一番上の出来事の時系列（高さ 150px）と enum の内訳
  - 右：モックのウォッチと承認の欄の代わりに、レビュー待ち（未決の数、対象の内訳、影響の大きい問いの先頭、レビューへの入口）と OM の要約
- **法則（テスト）**：
  - 確信度の分布で、どの問いもちょうど1か所に数える
  - 数字の帯は API の件数と合計をそのまま使う
  - 小さな棒は最後の n 個で、最大が 100

- レビューの指摘で直したこと：
  - エラーの扱い：出来事の行が読めないときは出来事の欄だけを失敗にする。前の OM の DomainIndex を使わないようにした
  - 契約の値を黙って補わない：reviewer、エンティティグループの数
  - 確信度の分布：閾値をまたぐ区間も、候補の分だけ色を付ける
  - 0 件の区切りは棒にしない
  - 印（← / ⇄）の決め方を1か所に
  - 死んだ CSS を消した。並べ方と「開けるか」の判定を純粋な関数にしてテストした
- 地図を作り直した直後に、読み込み中の地図へ設定をして例外になっていた。設定は「読み込みの終わった地図」にだけ行う。
  スモークテストに運用室を足した（この例外は、それまで運用室を開いていなかったので見逃していた）
- OM の一覧の契約に reviewable を足した（レビューの列を読めるかはサーバが決める）。正解 OM の運用室は、レビュー待ちの代わりに
  「レビューしない OM」と出す

## 積んだもの（バックエンドが要る）
- **Model（1c）**：
  - 表の設計画面：種類、粒度、同一性、意味型、表示アノテーション、OM が生む UI
  - ブランチへの保存（T6.2 の git / PR）と、表示アノテーション（T5.1）が前提
- **Query（1f）**：
  - たどりと尺度の組み立て。粒度と加法性で集計を守り、出所を常に出す
  - 汎用のグラフ問い合わせ（T5.3）と、尺度の定義が前提
- **ウォッチと承認カード**：オペレーター（仕様 8 章）、命令（7.3）、承認の列（8.3）が前提
- **取り込みの統計（1d の右の列）**：
  - 実行の記録（runs/*.json）を API で返せば出せる（主張の数、自動で決めた数、衝突）
  - 今は出していない
- **地図の点の疑わしい位置**：(0, 0) の点 918 件の扱い（印を付けるか）。T1.10 の気づき

## 既知
- Barlow には日本語の字形が無いので、日本語は Hiragino Sans / Noto Sans JP で出る
- グラフの全体のレイアウト（cose）は、選んでいないときに細長くなることがある。選ぶとその近くに寄る
